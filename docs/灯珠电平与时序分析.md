# 灯珠电平与时序分析

依据是 `docs/E1004CAA80592E31D08BFE019083806F.pdf`，星历 XL-5050RGBC-WS2812B 技术数据表，共 17 页。下面所有"P5""P10"指该 PDF 页面右下角的印刷页码。实测条件：主板 USB-C 供电，子板直插装甲板 1 号座，万用表量得子板灯带 VDD 为 4.8V。

## 0. 结论修订（2026-10-20，最终版）

**灯不亮的真正原因既不是电平也不是码元宽度，是固件里 RMT 编码器的电平位没写。** 排查过程与判据见 `docs/调试指南_OpenOCD_GDB.md §0`。

`armour_leds_init()` 里原来这样配：

```c
.bit0 = { .duration0 = 4, .duration1 = 8 },
.bit1 = { .duration0 = 8, .duration1 = 4 },
```

`rmt_bytes_encoder_config_t` 的 `bit0/bit1` 类型是 `rmt_symbol_word_t`，位域为 `duration0:15 | level0:1 | duration1:15 | level1:1`，驱动把这两个模板**原样**塞进符号内存，不会代填 level。C 的指定初始化器把没写出来的 `level0/level1` 静默置 0，于是每个码元两段都是低电平——数据线恒低。用 GDB 读通道 0 的符号内存 `0x60016400`，47 个词全是 `0x00040008`，解码即 duration0=8、**level0=0**、duration1=4、level1=0，与推断一致。补上 `.level0 = 1, .level1 = 0` 后立刻点亮，片内回读也从 `hi=0 edges=0` 变成 `hi=220 edges=125`。

这条坑隐蔽在于它一切"成功"：`rmt_transmit` 返回 ESP_OK，TX-done 中断正常来，逻辑分析仪/万用表却什么也看不到。所以 §1–§5 的电平推导从头到尾都是错的方向，保留仅作规格阅读；**不要据此动硬件**。

本文改过两次结论，记录一下轨迹以免误导后人：
1. 初版：手册 VIH=0.7×4.8V=3.36V > C3 的 3.3V，判"必须加电平转换"。
2. 二版：负责人给出同型号硬件的开源实机 SmallMaster（`github.com/njupt-robomasters/SmallMaster`，无电平转换器能点亮），电平说被推翻，改判"嫌疑在码元宽度"，把 0 码从 300ns 调到 400ns。
3. 本版：对齐参考时序后仍不亮，才用调试器读符号内存定位到 level 位。时序数值最终就取参考实现的 0=400/800ns、1=800/400ns，本板已实测点亮。

手册 P5 的 VIH=0.7VDD 只是最小值保证，这批灯珠实际门限明显更低——参考板和本板都是 3.3V 直驱 4.8V 轨点亮的。

§1–§5 保留，作为规格层面的推导；§4 的三个硬件方案在本板已确认不需要，留作换灯珠/换供电轨时的备选。

## 1. 门限从哪来

P5 电性参数表（光电参数，Ta=25℃）：

> 高电平输入电压 High level input voltage ｜ Vih ｜ 最小值 Min. **0.7VDD** ｜ 代表值 Typ. --- ｜ 最大值 Max. --- ｜ 单位 V
> 低电平输入 Low level input ｜ Vil ｜ --- ｜ --- ｜ **0.3** ｜ V

门限写成 VDD 的函数而不是固定电压，供电越高它跟着涨。低电平那栏倒是绝对值 0.3V，说明手册对两端并不对称。

代入实测：0.7 × 4.8V = 3.36V。C3 的高电平由自身 VDD 决定，本板 3V3 出自 ME6118A33，标称 3.3V，扣掉 LDO 精度和负载调整率通常在 3.2~3.35V。缺口最理想 0.06V，加上走线压降和驱动级内阻实际有 0.1~0.3V。

反过来算，3.3V 信号最多能配多大的灯带轨：3.3 / 0.7 = 4.71V。留 0.3V 噪声余量就该压到 4.3V 以下。实测 4.8V 超线 0.5V，谈不上贴边。

手册通篇没有"3.3V 逻辑兼容"或"5V 供电下可用 3.3V 驱动"这类条款。P6 最大绝对额定值只写了「逻辑输入电压 V1 ｜ -0.5~5.5 ｜ V」，那是耐压上限，跟能不能被判成高电平是两件事。

## 2. 把灯带改接 3V3 行不行

不行，三处条款各自堵一道。

P4 特性说明第 1 条「电源输入电压：3.5-7.5V」，P5 电性参数同样写 Vin 最小 3.5V。3.3V 低于最小工作电压。P6 绝对额定值里写的是「逻辑电源电压 Vin ｜ 3.0-7.5」，那是"接了不会烧"的下限，不是"能工作"的下限，两者不能混用。

P7 电压分档（测试条件 IF=20mA）给出各色压降：红 2.0~2.4V，绿 2.8~3.2V，蓝 2.8~3.2V。VDD 若是 3.3V，蓝绿通道留给片内恒流源的压差只剩 0.1V。

而 P4 第 2 条和 P5 都写明「OUT R/G/B 恒流值：12mA」。0.1V 压差撑不住一个 12mA 的恒流管，结果是蓝绿严重欠流或者干脆不亮，白平衡跟着崩。

所以降压这条路只能有限地降。降到 3.8~3.9V 是手册允许范围内的最低位置（仍高于 3.5V，恒流管还有 0.6~0.7V 压差），对应门限 2.66~2.73V，3.3V 信号余量 0.57V。

## 3. 时序：代码确实有一处要改，但它救不了电平

P10 码型时间表：

> T（码元周期）｜ 0.89 ｜ --- ｜ --- ｜ µs
> TOH（0 码，高电平时间）｜ 0.2 ｜ 0.295 ｜ 0.35 ｜ µs
> TOL（0 码，低电平时间）｜ 0.55 ｜ 0.595 ｜ 1.2 ｜ µs
> TIH（1 码，高电平时间）｜ 0.55 ｜ 0.595 ｜ 1.2 ｜ µs
> TIL（1 码，低电平时间）｜ 0.2 ｜ 0.295 ｜ 0.35 ｜ µs
> TRST（Reset 码，低电平时间）｜ 80 ｜ --- ｜ --- ｜ µs
>
> 注 1：写程序时，码元周期最低要求为 0.9us
> 注 2：0 码、1 码的高电平时间需按照上表的规定范围，0 码、1 码的低电平时间要求小于 15us

P9 动态参数给数据速率的测试条件是「fDIN ｜ 800 ｜ KHZ ｜ 占空比 67%（数据 1）」，P5 的「开光说明」一节（手册原文如此，当为"开关"之误）给速率上限「FDIN ｜ --- ｜ 800 ｜ 1100 ｜ kHz」。

原代码在 10MHz 分辨率（1 tick = 100ns）下取 bit1 = 600ns 高 / 600ns 低。TIH 窗口是 550~1200ns，600ns 距下限只剩 50ns；电平本来就贴边，DIN 要花时间爬过 0.7VDD，有效高电平宽度会被削短，削掉 50ns 就出窗，1 码被读成 0 码。改成 800ns 高 / 400ns 低之后，距下限有 250ns 余量，占空比 800/1200 = 66.7%，跟 P9 的 67% 测试基准正好对上。码元周期仍是 1.2µs，高于注 1 要求的 0.9µs，速率 833kbps 在 1100kbps 以内。低电平 400ns 超出表格里的 TIL 上限 350ns，靠注 2 放行（只要求小于 15µs）。bit0 原本取 300ns / 900ns，理由是 TOH 典型值就是 295ns，落在正中——但 §6 的参考实现用的是 400ns 高 / 800ns 低并且实测能亮，比手册上限还宽 50ns，说明这个窗口的实际判据比表格宽松。现已把 bit0 一并改成 400/800，与参考实现完全一致。

其余核对下来是对的。P10 协议数据格式写的位序是「G7 G6 G5 G4 G3 G2 G1 G0 R7…R0 B7…B1」，高位在前，与 `armour_leds.c` 里 `grb[][3]={G,R,B}` 加 `msb_first=1` 一致。TRST 要求 80µs，固件帧间隔 6ms，空闲时数据线钉低（推挽低电平约 0V，满足 P5 的 VIL 0.3V）。子板实装 3 颗而固件按 `ARMOUR_LED_MAX=4` 发，多出的 24bit 按 P3「接受够 24Bit 后，DOUT 端开始转发数据」被末级转发出去、没有接收者，无害。驱动档顺手拉到 `GPIO_DRIVE_CAP_3`，这一条手册没有依据，属于工程判断：边沿陡一点，脉冲顶部早一点到位。

顺带用 P4/P5 的 12mA 核定一下电流：每颗全白 3×12 = 36mA，四边 16 颗就是 576mA，超过 USB 默认 500mA。当前 `CONFIG_ARMOUR_BRIGHTNESS=160`（约 63% 占空）算下来 360mA，够用。P5 的静态功耗「LDD ｜ --- ｜ 0.3 ｜ --- ｜ MA」每颗 0.3mA，可忽略。

## 4. 三个硬件方案（后备，先做 §6 的对照实验）

以下三个方案的前提是"换了参考时序、量过线是通的，仍然不亮"。在 §6 的证据下，这一步大概率不需要。

**A. 数据线加上拉，C3 配开漏。** 每根 `WS_x` 对灯带轨挂上拉电阻，固件把该脚设成开漏：低电平由 C3 主动灌地，高电平释放、由上拉把线充到轨压。上拉的目标网络就是灯珠 VDD 本身（同一张 5V 网络，实测 4.8V），所以高电平直接是 4.8V，对门限 3.36V 余量 1.44V，且低于 P6「逻辑输入电压 V1 = -0.5~5.5V」的上限。这里用不到 DIN→VDD 的内部钳位二极管，它要 DIN 高于 VDD+0.6V（约 5.4V）才导通。

上拉阻值受上升沿约束，而且约束比直觉严厉得多。RC 充电 V(t) = V轨(1 − e^(−t/τ))，τ = RC，跨过头限 0.7×V轨 需要 t = τ·ln(1/0.3) ≈ **1.2τ**（注意 τ 和 10–90% 上升时间 2.2τ 都不是"能用的时刻"，判据是 1.2τ 对 TOH 的侵蚀）。下降沿由 C3 主动灌地，几十 ns 以内，可忽略。按全线 50pF（3 颗灯输入电容 + 排线 + 焊盘）估：

| 上拉 | τ | 过门限耗时 | 有效 T0H（标称 300ns） | 有效 TIH（标称 800ns） |
|---|---|---|---|---|
| 4.7k | 235ns | 282ns | 18ns | 518ns |
| 2.2k | 110ns | 132ns | 168ns | 668ns |
| 1k | 50ns | 60ns | 240ns | 740ns |

对照 P10 的窗口 TOH 200~350ns、TIH 550~1200ns：**瓶颈在 0 码不在 1 码**。2.2k 时 1 码仍有 668ns 稳稳在窗内，0 码却已被削到 168ns、出窗；1k 时两者都在窗内（240ns / 740ns），低电平灌电流 4.8V/1k = 4.8mA，对 C3 的灌电流能力毫无压力。所以先前写的"2.2k 可以、4.7k 偏紧"是错的，实际是 4.7k 完全不可用、2.2k 不合格。

因此 A 的落地要把两件事一起做完：

1. 实测开漏波形——RMT 经 GPIO 矩阵驱动开漏脚能否出正确码元，手册管不了，只能量。
2. 实测全线负载电容，再定阻值。若实测 ≤35pF，2.2k 的有效 T0H 约 208ns，勉强过线；否则取 1k。
3. 备选：把 T0H 抬到 350ns 换取 50ns 余量，但 10MHz 分辨率下只能取 300 或 400（400 出窗），要 350 得把 RMT 提到 20MHz（80MHz APB / 4，50ns 一格），而且 350 正压在窗口上限，不如直接换 1k 实在。

**B. 灯带轨串二极管降压。** 子板 VDD 进线串 2 只肖特基，4.8V 降 0.9V 到 3.9V，门限变 2.73V，3.3V 信号余量 0.57V。3.9V 仍高于 P4 的 3.5V 下限，恒流管压差 0.7V。纯被动，固件一行不用改，缺点是亮度上限略降。只串 1 只管降到 4.35V、门限 3.05V，余量只剩 0.25V，不够稳妥。

**C. 加 74AHCT125 电平转换。** 5V 供电的 buffer，3.3V 进 5V 出，四边各一路，高电平约 5V，彻底解决。要改板或飞芯片，工作量最大。

建议按 A、B、C 的顺序试：A 元件最少又不动电源轨，A 若开漏路径实测不通，B 是必定成功的兜底。

## 5. 还没查清的部分

§1–§3 是规格层面的推导。它当时推出的"必须改硬件"已经被 §6 的开源实机证据否掉，但下面几件事仍然没有测过：

插座 pad1 到首珠 DIN 通不通，从来没测过。之前万用表直流档读 WS 线 0V 属正常现象——稀疏帧的直流平均本来就接近 0，那次读数既不能证明断线也不能证明通路。

还有个容易误读的地方：诊断用的 tone 模式（`loop_count=-1` 连续重发全白帧）只能证明线上有信号，看不到点亮。因为 P3 写明「当接受到 80us 以上的低电平 RESET 码后，芯片将接受到 24Bit PWM 数据脉宽输出到 OUTR，OUTG，OUTB 上」，而连续帧之间没有 80µs 的低电平，芯片根本不锁存。全 1 码占空比 67%，所以万用表直流档的期望读数是 0.67×3.3 ≈ 2.2V（原先按 600/600 写的 1.6V 已作废）。

排查顺序：先烧 §6 对照出来的参考时序看亮不亮；不亮再用蜂鸣档量 pad1 到首珠 DIN 通不通（一分钟，不用改任何东西）；线通了仍不亮才动 §4 的电平方案。灯珠引脚定义在 P13：1 VDD、2 DOU（数据输出）、3 GND、4 DIN。P11 还提到「电容常规接 104 贴片电容」，并给了无电容和加电容两张参考线路图，可以顺便看看子板每颗灯 VDD-GND 之间有没有贴 100nF。

## 6. 开源实机参考：SmallMaster（推翻"必须改硬件"）

硬件负责人指出本检测装置参考南京邮电大学 Potential 战队的开源装甲板 `https://github.com/njupt-robomasters/SmallMaster`。把它的固件源码和随仓库发布的 PCB 工程 `裁判系统/PCB/ProPrj_校内赛装甲板_2025-11-21.epro2` 拆开对照，与本板重合度极高：

| 对照项 | SmallMaster | 本工程 |
|---|---|---|
| 主控 | ESP32-C3-WROOM-02U-N4（`platformio.ini`: `board = esp32-c3-devkitm-1`） | 同型号同封装 |
| 灯珠 | BOM 内 `XL-5050RGBC-WS2812B` | 同型号 |
| 灯带数据脚 | `hit.cpp`：`Adafruit_NeoPixel(3,10)`/`(3,5)`/`(3,6)`/`(3,7)` = 前/后/左/右 | GPIO10/5/6/7 同一分配 |
| 每边灯数 | 3（`fill(color, 0, 3)`） | `ARMOUR_LED_MAX=4`，多发 1 颗无害 |
| 传感脚 | `adc_pins[4] = {0,4,3,1}`（前/后/左/右） | 按键总线 GPIO0/1/3/4，同一组脚 |
| 电源链 | SS34 + SMAJ5.0A + ME6118A33PG + 5.1k + 100nF/10uF | 完全一致 |
| 电平转换 | **BOM 全部 15 种器件里没有 buffer/转换器** | 同样没有 |
| 网络名 | `WS_F/B/L/R`、`ADC_F/B/L/R`、`BOOT/KEY`、`IO8`、`TXD/RXD`、`IN_B` | 同名，同一套设计 |

也就是说：**同一颗 3.3V 输出的 MCU、同一颗灯珠、同一组脚、没有任何电平转换，人家能点亮。** 手册 P5 的 VIH=0.7VDD 是最小值保证，实际门限显著低于它——这不是推断，是别人板子上的事实。

更能说明问题的是它的时序。SmallMaster 用 `Adafruit_NeoPixel@^1.15.1`，其 IDF≥5 的 RMT 路径在 `esp.c` 里写死（10MHz 分辨率，1 tick = 100ns）：

```c
if (pixels[b] & (1<<(7-bit))) { led_data[i].duration0 = 8; led_data[i].duration1 = 4; }  // 1 码 800/400ns
else                          { led_data[i].duration0 = 4; led_data[i].duration1 = 8; }  // 0 码 400/800ns
```

0 码高电平 400ns，**超出 P10 表格 TOH 上限 350ns 达 50ns，却正是它点亮了这批珠子**。反过来看我们原来的 300ns：手册上合规，实际比参考实现窄 100ns。如果灯珠内部判 0/1 的门限在 350~400ns 附近（这批克隆片的常见做法），300ns 的 0 码会被判成 1 或判不进，整帧解码错乱，表现就是完全不亮。

顺带两条架构印证：`esp.c` 用 `static int rmtPin` 只占**一个** RMT TX 通道，换引脚时 `rmtDeinit()` + `rmtInit(pin, RMT_TX_MODE, RMT_MEM_NUM_BLOCKS_1, 10000000)`，加互斥锁串行化——和我们 `remux_channel()` 的"单通道 × 换 GPIO 轮转"是同一个方案，只是我们用 `rmt_tx_switch_gpio` 免掉了重建开销。它每通道只申请 48 symbol（3 灯 72 symbol 靠驱动内部回绕搬运），我们申请 96 让整帧一次装下。

值得从它那儿借鉴的还有业务侧（`code/armor/src/`）：`hit.cpp` 用 ADC DMA 以 40kHz 总采样率轮询 4 路压电、`HIT_THRESHOLD=2000` 判击打、`HIT_BLINK_MS=50` 作冷却窗，击打期间 `clear()+show()` 让该边熄灭一下再恢复常亮——我们改成机械键后不能照抄阈值和 DMA，但"触发→短暂反色/熄灭→恢复"这个视觉语法和冷却窗结构可以直接用。`main.cpp` 用 OneButton 把 KEY0(GPIO9) 做成短按切红/蓝、长按进 ESP-NOW 配对，颜色用 `Preferences`（NVS）持久化，另一路 `Serial0(20,21)` 转发 DBUS；这套按键语义和回传帧格式（`air.hpp` 的 `packet_t{color,hit_cnt,dbus[10],rssi}`，100ms 超时清零）是我们做无线控制那一步的现成参照。
