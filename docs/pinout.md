# 装甲板引脚分配（pinout）— 计划步骤 1 产出

> 来源：解析 `ProPrj_装甲板_2026-10-17.epro2` 内 PCB 网表（`PAD_NET` 记录）+ 模组符号引脚表 + 本机 ESP-IDF `soc/adc_channel.h`、`esp_hal_rmt/esp32c3/rmt_periph.c` 核对。解析日期 2026-10-18。

## 1. 核心结论（先改认知）

**`ADC_F/B/L/R` 不是电流采样，是四边"按键总线"**：
每边子板装 3~4 只侧按键（CPG151101D01，2 pad：信号=IN_x，另一极=GND），同边所有按键**并联**在一条返回线上；主板把该线上拉 5.1kΩ 到 3V3，经模组进 GPIO。按下任一键→该边线拉低。
- 固件应把这 4 路按**数字输入**轮询（也能当 ADC1 采样读，通道全在 ADC1）。
- 硬件限制：**同一边的多只按键不可区分**（无分压梯度，全并 GND），只能感知"该边有按键按下"。

**RMT TX 通道只有 2 个，数据有 4 条线**：`rmt_periph.c` 中 C3 ch0/ch1 有 tx_sig、ch2/ch3 只有 rx_sig → 最多 2 路并行 WS2812 输出。WS2812 帧间自保持，可**时分轮转刷新**（2 个通道轮流删除/重建映射到 4 条线），或先广播式"两边同图"简化。

**ADC 通道无冲突、无需改板**：四路按键线恰落在 GPIO0/1/3/4，全属 ADC1。

## 2. GPIO 总预算表（WROOM-02U 全部 15 个引出脚）

| GPIO | 板上网络 | 功能分配 | 约束备注 |
|---|---|---|---|

| 1 | `ADC_R` | 右边按键总线（R18） | ADC1_CH1 |
| 2 | `$1N96`(未引出) | **空闲**，R14 上拉到 3V3 | strapping（io_sel），勿外接驱动 |

| 6 | `WS_L` | 左边灯带数据输出 | 同上 |
| 7 | `WS_R` | 右边灯带数据输出 | 同上 |
| 8 | `IO8` | **空闲**输入，R13 上拉 | strapping（download boot mode） |
| 9 | `BOOT/KEY` | 主板按键 KEY0（R12 上拉） | strapping：复位时按住=进 USB 下载 |

## 3. 四边子板接口（PH2.0 4P，主板×4 → 子板×1 同型插座）

| 插座脚 | 主板网络 | 子板对应 | 方向 |
|---|---|---|---|
| 1 | `WS_x` | 灯带首珠 DIN | MCU→子板 数据 |
| 2 | `ADC_x` | `IN_x` 按键总线 | 子板→MCU |
| 3 | `GND` | GND | — |
| 4 | `5V` | 灯带 VDD（SS34 之后） | 电源 |

子板实物：3~4 颗 XL-5050RGBC-WS2812B 手拉手（DOUT→下珠 DIN，末级 DOUT 悬空）+ 3~4 只侧按键。网表内三块子板 PCB 文档的灯数分别为 4/3/3，且网络均标 `WS_B/IN_B`——**四边各自的设计应以同一接口合同（§3 表）为准**。

## 5. 电平匹配（灯带 5V 轨）— 依 `docs/E1004CAA80592E31D08BFE019083806F.pdf` 定稿

> 逐条引文、页码标注与推导过程见 **`docs/灯珠电平与时序分析.md`**（本 §5/§5.1 是其摘要）。

灯珠 XL-5050RGBC-WS2812B（星历）关键额定值：

| 参数 | 值 | 出处 |
|---|---|---|
| 电源输入 Vin | **3.5 ~ 7.5V**（绝对最小 3.0V） | 特性说明 / 电性参数 |
| 高电平输入 VIH | **0.7×VDD** | 电性参数表 |
| 低电平输入 VIL | ≤ **0.3V**（绝对值，非 0.3×VDD） | 电性参数表 |
| 逻辑输入电压 V1 | −0.5 ~ 5.5V | 最大绝对额定值 |
| RGB 恒流 | 12mA/通道（静态 0.3mA） | 特性说明 |
| 红/绿/蓝 Vf | 2.0~2.4 / 2.8~3.2 / 2.8~3.2V | 电压分档 |

实测灯带轨 4.8V，按手册公式门限是 0.7×4.8 = 3.36V，高于 C3 的 3.3V 输出。**但这是最小值保证，不是实测判据**：本板参考的开源实机（SmallMaster，同型号 C3 + 同型号灯珠 + 无电平转换器）能正常点亮，其驱动用的 0 码高电平 400ns 还超出了手册 TOH 上限 350ns。**本板现已用 3.3V 直驱实测点亮，下列 A/B/C 三个硬件方案全部确认不需要动用**——当初"灯不亮"的元凶是固件 RMT 编码器漏写电平位，见 `灯珠电平与时序分析.md §0`。方案留档仅供换灯珠/改供电轨时参考。

省事的想法"把灯带也接 3V3"仍然不要做：3.3V 低于手册的 3.5V 最小工作电压，且蓝/绿 Vf 高到 3.2V，片内 12mA 恒流源只剩 0.1V 压差，稳不住流。

可选修复，按改动量排序：

1. **数据线上拉 + 开漏输出**：每根 `WS_x` 对灯带轨（同一张 5V 网络，实测 4.8V）挂上拉，固件把该脚配成开漏（`GPIO_MODE_OUTPUT_OD`）。高电平直接充到轨压 4.8V，对门限 3.36V 余量 1.44V，低于 V1 的 5.5V 额定；低电平由 C3 灌地。阻值受上升沿约束：RC 充电跨过头限 0.7×V轨 需要 1.2τ（τ=RC），50pF 负载下 4.7k 削掉 282ns、2.2k 削 132ns、1k 削 60ns。TOH 只有 300ns，窗口下限 200ns，故 4.7k 与 2.2k 都会把 0 码削出窗，**取 1k**（有效 T0H 240ns、TIH 740ns，灌电流 4.8mA）。前置实测两件事：RMT 经 GPIO 矩阵驱动开漏脚能否出正确波形、全线实际负载电容。推导见 `灯珠电平与时序分析.md` §4。
2. **灯带轨串二极管降压**：串 2 只降到 3.8~3.9V，门限 2.7V，余量 0.6V，且高于 3.5V 下限；只串 1 只管降到 4.3V，门限 3.0V，余量 0.3V 偏紧。代价是恒流源压差降到 0.6~0.7V，亮度上限略降。
3. **加电平转换器 74AHCT125（VCC=5V）**：彻底解决，改板项，四边各一路 buffer。
4. 固件侧已配 `GPIO_DRIVE_CAP_3`（四条 WS 线最高驱动档，让 400ns 窄沿尽量陡）。实测点亮不依赖它，留着无害。

## 5.1 时序合同（写驱动时照此，勿照抄 IDF 树内 WS2812 示例）

| 码元 | min | typ | max | 本工程实现（10MHz，1tick=100ns） |
|---|---|---|---|---|
| T0H | 200ns | 295 | 350 | 400ns（超表格上限，取参考实现值） |
| T0L | 550ns | 595 | 1200 | 800ns |
| T1H | 550ns | 595 | 1200 | 800ns |
| T1L | 200ns | 295 | 350 | 400ns（超出表格，靠注 2 放行：低电平 <15µs） |
| 码元周期 | ≥0.89µs | — | — | 1.2µs → 833kbps（上限 1100kbps） |
| TRST | ≥80µs | — | — | 帧间隔 ≥6ms；空闲脚钉低 |
| 数据格式 | G7..G0 R7..R0 B7..B0，MSB first | | | `grb[][3]={G,R,B}` + `msb_first=1` |

最后一列的高电平 400/800ns 不是照手册算的，是照 `github.com/njupt-robomasters/SmallMaster` 的驱动抄的：它用 Adafruit_NeoPixel 的 IDF≥5 RMT 路径（`esp.c`），10MHz 下 0 码 4/8 tick、1 码 8/4 tick，同一颗 C3 加同一批 XL-5050 实测能亮。手册窗口与它冲突时以实机为准。**本板按此数值已实测点亮。**

另有一条比数值更要命的合同：`rmt_bytes_encoder_config_t.bit0/bit1` 里的 `level0/level1` **必须显式写**（`level0=1, level1=0`）。驱动把这两个模板原样塞进符号内存、不代填电平，漏写等于发一条恒低的线，而 `rmt_transmit` 照样返回成功。符号字判据见 `调试指南_OpenOCD_GDB.md`。

## 6. 对计划的强制修正

1. "四边电流采样/armour_adc(电流)" → 改为 **"四边按键总线/armour_btn（数字输入轮询）"**；ADC 读法降为可选。
2. `armour_leds` 刷新调度（已实现）：**单 TX 通道 × 轮转 4 边**——通道 `mem_block_symbols=48`（C3 每通道 48 symbol、无 DMA），3 灯一帧 72 symbol 由驱动的半内存 ISR 回填，实测无丢帧；经 `rmt_tx_switch_gpio` 换脚轮转。原"2 TX 通道"方案因此弃用。SmallMaster 的 `esp.c` 也是"一个共享 TX 通道 + 换脚时 deinit/init"，印证该方案成立。
3. 每边灯珠数 `ARMOUR_LED_MAX=3`（子板实测 3 颗，与参考实现一致；曾按 4 定宏，多出的第 4 颗发的是全 0 像素，不影响点亮但没必要）。
